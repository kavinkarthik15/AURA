## Policy Metrics

- Policy Version: policy_v1
- Top-1 Accuracy: generated by `PolicyEvaluator`
- Average Probability: generated by `PolicyEvaluator`
- Coverage: generated by `PolicyEvaluator`
- State Coverage: reported for Python, DSA, projects, and other observed state keys
- Goal Coverage: reported per goal
- Entropy: normalized policy entropy
- Confidence: successful support-based confidence
- Drift: KL divergence and total variation

## Continual Learning Metrics

- Replay statistics: total, duplicate removal, success/failure, sampled count, average goal progress
- Dataset merge metadata: base, experience, merged counts, timestamp
- Candidate benchmark: MAE, MSE, R²
- Deployment decision: accepted or rejected with reason
- Registry lineage: parent model, parent policy, dataset hash, training source, and acceptance state
- Rollback: previous active policy restored after benchmark failure

## Retrieval-Augmented Planning Metrics

- Retrieval Version: retrieval_v1
- Similarity Metric: hybrid cosine, weighted, goal, and action-overlap score
- Retrieval Weight: 0.4
- Top-K: 3
- Retrieval Precision and Recall: generated by `RetrievalEvaluator`
- Average Similarity: generated by `RetrievalEvaluator`
- Retrieval Time: exposed in planner performance timings
- Retrieval Cache: enabled by configuration
- Diversity Filter: enabled for near-duplicate Top-K results

## Performance Timing

The system records subsystem timings in `performance_timings_ms` when available:

- Planning time
- Beam-search time
- Policy inference time
- Digital-twin simulation time
- Execution time
- Experience logging time
- Training time
- Deployment time

Beam search currently exposes `beam_search` timing directly. The shared `PerformanceBenchmark` utility is available for instrumenting the remaining subsystems.
